#### 0. Команды Linux, которые вам могут потребоваться
- `pwd`

    Абсолютный путь текущей директории
<br/>

- `ls`

    Отобразить содержимое директории
<br/>

- `ls -a`

    Отобразить содержимое директории, включая скрытые файлы и каталоги
<br/>

- `cat`

    Отобразить содержимое файла/файлов
<br/>

- `mkdir`

    Создание директории
<br/>

- `rm`

    Удаление файла/файлов
<br/>

- `rm -r `

    Удаление директории, включая вложенные файлы и каталоги
<br/>

- `cp`

    Копирование файла/файлов
<br/>

- `cp -r`

    Копирование директории, включая все вложенные файлы и каталоги
<br/>

- `mv`

    Перемещение файлов/директорий
<br/>

#### 1. Обновить пакеты после установки Linux

Для Ubuntu, Debian и многих других:
```
sudo apt update
sudo apt full-upgrade
sudo apt autoremove
sudo apt autoclean
```
<br/>

Для других дистрибутивов команды могут отличаться.

К примеру, для CentOS это `sudo yum update`, etc.

---
#### 2. Установка git
Выполнить в терминале
```
sudo apt install git
```

#### 3. Генерация ssh-ключей для git
Для того, чтобы репозиторий не был для вас приватным и его можно было склонировать, вносить в него изменения, необходимо сгенерировать ключи и добавить их в свой аккаунт на Gitlab.
<br/>

Выполнить в терминале (как один из вариантов):
```
ssh-keygen -t rsa -b 2048
```
<br/>


Вас попросят придумать `passphrase`. <br/>Это должно быть что-то простое (к примеру, набор из 5-6 символов).
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/keygen.png)
<br/>

В директории `~/.ssh` будут созданы 2 ключа: публичный (`id_rsa.pub`) и приватный (`id_rsa`).<br/>
<font color="green">Публичный ключ можно распространять.</font> <br/><font color="red">Приватный ключ нельзя распространять ни при каких условиях (**!**).</font>
<br/>

Директория `.ssh` расположена в `Домашней папке`, но не отображается, поскольку имена скрытых файлов и директорий начинаются с точки `.`
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/ff.png)
<br/>

Для их отображения нажимаем `Ctrl+H` (либо выставляем соответствующий флаг в настройках окна).
<br/>

Директория `.ssh` отобразилась:
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/12.png)
<br/>

В ней находятся два ключа: `id_rsa.pub` и `id_rsa`:
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/keygen4.png)
<br/>

Далее заходим в репозиторий проекта -> `Preferences` (у вас будет другой URL):
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/keygen6.png)

<br/>

И добавляем содержимое файла `id_rsa.pub`.<br/>Жмем `Add key`.
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/keygen8.png)
Публичный ключ добавлен.
<br/>

Содержимое файла `id_rsa.pub` также можно отобразить, выполнив в терминале
```
cat ~/.ssh/id_rsa.pub
```
После чего скопировать его содержимое и вставить в форму.

#### 4. Клонирование репозитория

Код проекта каким-то образом должен присутствовать на вашем PC.
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/clone.png)
Копируем адрес из `Close with SSH` и вставляем его в терминал, выполняя
```
git clone git@gitlab.com:msu_c_course/....git
```
<br/>

В вашей текущей директории появится **локальный репозиторий** (в данном случае это `some_student_102`).
![img](https://gitlab.com/alexfmsu/tmp/-/raw/main/keygen2.png)
<br/>
Переходим в локальный репозиторий
```
cd some_student_102
```

    ![git_105](https://gitlab.com/alexfmsu/tmp/-/raw/main/git_105.png)

- Исправление замечаний

    Все комментарии по вашему коду будут приходить на почту.

    Отписав все замечания, ревьюер ставит "+" в лс telegram (пока так).

    Комментарии привязываются к конкретной строке/строкам.

    Также комментарий может быть привязан в первой строке в случае, когда он касается общих замечаний по коду: отсутствие табуляции, отсылки к Codestyle.html и пр.
    ![git_106](https://gitlab.com/alexfmsu/tmp/-/raw/main/git_106.png)
    <br/>

    Исправления выкатыватся путем создания нового коммита:
    - исправили код
    - `git add имя_исправленного_файла`
    - `git commit -m 'task 01 fixed'` (к примеру)
    - `git push`

    <br/>

    Создавать новую ветку и/или открывать новый `merge request` не нужно.

    Вопросы, оспаривание замечаний и пр. нужно оставлять в том же треде.<br/>
    Если вы считаете, что замечание исправлено, нажимаете "Resolve thread".

    После закрытия всех замечаний (All threads resolved), ставьте "+" в лс telegram-а ревьюера.<br/>

    <br/>
	 Пример выкатки фикса (исправленный файл 01.с):

    ![git_107](https://gitlab.com/alexfmsu/tmp/-/raw/main/git_107.png)
    <br/>


    Команда
    ```
    git diff --staged 01.c
    ```
    покажет добавленные/измененные/удаленные строки в файле, добавленном в индекс (после `git add 01.c`).

    <br/>

    Резолвим тред:
    ![git_150](https://gitlab.com/alexfmsu/tmp/-/raw/main/git_150.png)

    <br/>

- Получение аппрува

    После того, как ревьюер зааппрувит ваш `Merge Request`, нажимаем `Merge`.

    Код вашей ветки вольется в ветку `master`.

    ![git_109](https://gitlab.com/alexfmsu/tmp/-/raw/main/git_109.png)<br/>

    Далее заливаете принятые задачи на `earth.ispras.ru`, в последний раз убеждаясь, что код проходит тесты.

    Уведомляете ревьюера, что всё "ОК".

    Ревьюер засчитывает сданные задачи, проставляя их в таблице.
